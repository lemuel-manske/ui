# Getting started

This library provides React 19 components, compound parts, hooks, and semantic design tokens.

Import public APIs from `@lemuel-manske/components` and `@lemuel-manske/design-tokens`. Avoid deep imports into `src` or `dist`.

## Installation

Packages are published to GitHub Packages. Configure the `@lemuel-manske` scope in your application's `.npmrc` and authenticate through your normal GitHub Packages workflow:

```ini
@lemuel-manske:registry=https://npm.pkg.github.com
```

```sh
npm install @lemuel-manske/components @lemuel-manske/design-tokens
```

## Styles and theme

Import the component CSS once in your application's entry point. The component entry also imports the design token stylesheet.

Wrap your UI in `Theme` to choose a theme; use `archiveTheme` or `libraryTheme` from the tokens package.

```tsx
import '@lemuel-manske/components/styles.css';

import { Button, Theme } from '@lemuel-manske/components';
import { archiveTheme } from '@lemuel-manske/design-tokens';

export function App() {
  return (
    <Theme theme={archiveTheme}>
      <Button onClick={() => console.log('Save requested')}>
        <Button.Label>Save</Button.Label>
      </Button>
    </Theme>
  );
}
```

Storybook supplies a theme decorator. Application code needs its own theme wrapper.

The toolbar's brand switch changes the preview theme, not component props.

## Choosing pieces

- Use `Button` for actions and `Link` for navigation.
- Use `Field` for one control with its label, help text, and error message.
- Use `Fieldset` with `Fieldset.Legend` to group related controls.
- Use `Form` for native submission semantics and compose standalone controls inside it.
- Use `Combobox` for a native select with `Combobox.Option` children; it is not a searchable input.
- Use `Heading`, `Text`, and semantic tokens when composing application layouts.

Check each component's API before adding props. Supported props differ between components; do not assume arbitrary native attributes or props from another library are forwarded.

## Design tokens

CSS variables follow `--ui-{group}-{token}`, for example `--ui-space-16`, `--ui-color-text-primary`, `--ui-action-primary`, and `--ui-state-danger`.

Use action tokens for interactive colors and state tokens for focus and validation.

Keep token groups flat and semantic. A custom theme must satisfy the complete `DesignTokens` contract; start by spreading an existing theme and overriding complete groups as needed.

```tsx
import { archiveTheme, type DesignTokens } from '@lemuel-manske/design-tokens';

const theme = {
  ...archiveTheme,
  font: { ...archiveTheme.font, body: 'system-ui, sans-serif' },
} satisfies DesignTokens;
```

Fonts named by the themes must be loaded by your application if you want them instead of the configured fallback fonts.

Layout and application data remain the application's responsibility.

See the Branding and theming guide to create brands, configure typography, and compose nested themes using the documented token contract.
