# Form

`Form` renders a native form with design-system styles. Your application owns submission,
async state, and application validation. Browser constraint validation
applies unless `noValidate` is set.

```tsx
import { Form, Button, Field, Input } from '@lemuel-manske/components';

export function WebsiteForm() {
  return (
    <Form
      aria-label="Archive website"
      onSubmit={(event) => {
        event.preventDefault();

        const data = new FormData(event.currentTarget);

        console.log(data.get('url'));
      }}
    >
      <Field required>
        <Field.Label>Website URL (required)</Field.Label>
        <Field.Control>
          <Input name="url" type="url" placeholder="https://example.com" />
        </Field.Control>

        <Field.Description>Enter a complete URL, including https://.</Field.Description>
      </Field>

      <Button type="submit">
        <Button.Label>Archive website</Button.Label>
      </Button>
    </Form>
  );
}
```

This recipe is rendered and exercised by the Components/Form AccessibleFields story.

## Compose standalone controls

Import Input, Textarea, Combobox, Label, Button, Field, Checkbox, RadioGroup, and Fieldset
from the package to compose the form. Supply a `name` on each control whose value should
appear in `FormData`. A Combobox is a native select and accepts Combobox.Option children.

## Accessibility and validation

Give the form an accessible name with `aria-label` or `aria-labelledby`.
Label every control. `Field` handles label and message associations; if you use
`Label` directly, connect its `htmlFor` to the control's `id` yourself.
Use an explicit submit button. Call `preventDefault()` for JavaScript submission.

Render conditional `Field.Error` messages for application errors. Do not infer a
form-level `errors` or `onValuesChange` API. For grouped controls use `Fieldset` with
`Fieldset.Legend`. See Components/Form for other native form examples.
